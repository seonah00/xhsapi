# 운영·복구 안내 (P0, 로컬/파일럿 기준)

이 문서는 로컬·파일럿 환경 기준입니다. 실제 호스팅은 아직 정하지 않았습니다(명세 15장). 배포·학생 초대·메일·결제는 별도 승인 전까지 하지 않습니다.

## 1. 구성 요소

| 구성 | 역할 | 실행 |
|---|---|---|
| PostgreSQL 16 (Supabase 호환) | 모든 도메인 데이터, RLS, 작업 큐(`app_jobs`), 비용 원장 | `pnpm db:local` (임시 클러스터 `.tmp/pg`, 포트 54329) |
| 웹 (`apps/web`) | 화면 + `/api/v1`, 서버 액션 | 개발 `pnpm dev:web`, 프로덕션 `pnpm --filter @xhs/web build && pnpm --filter @xhs/web start` |
| 워커 (`apps/worker`) | `app_jobs` 폴링·임대(lease) 실행, 매시간 만료 정리 | `pnpm dev:worker` |
| 비공개 파일 저장소 | 업로드 파일(메타데이터 제거 후) | `ASSET_STORAGE_DIR` (기본 `.data/assets`), 배포 시 Supabase 비공개 Storage로 교체 |

필수 환경변수는 `.env.example`을 따릅니다. 비밀값은 `.env.local` 또는 서버 secret에만 둡니다. 채팅·문서·git·로그에는 넣지 않습니다. `NEXT_PUBLIC_`에는 비밀을 넣지 않습니다.

## 2. mock 모드 보장

- `APP_DATA_MODE=mock`이 기본값입니다. API 키가 있어도 live로 바뀌지 않습니다.
- 웹·워커는 시작할 때 **외부 연결 차단 가드**를 설치합니다. 로그 `mock mode: outbound network guard active (web|worker)`가 그 표시입니다. 이후 루프백·DB 외 TCP 연결은 거부되고 `[network-guard] blocked outbound connection to …`가 남습니다.
- 운영 점검: 로그에서 `[network-guard]`를 검색합니다. 한 건이라도 있으면 원인을 조사합니다(`pnpm test:e2e`는 이 경우 실패합니다).
- `next dev`는 자체 버전 확인을 위해 npm 레지스트리 접속을 시도하므로, 가드 로그가 한 줄 남을 수 있습니다. 앱 동작과는 무관하며, 시연·검증은 프로덕션 빌드로 합니다.

## 3. 작업(job) 상태와 복구

- 비용이 드는 작업은 모두 **견적(5분·1회용) → 확인 → `app.reserve_and_enqueue`** 순서를 거칩니다. 이 단계는 한 트랜잭션으로 처리됩니다: 견적 소비, 예산 잠금, 원장 기록, 작업 생성, idempotency 키 저장.
- 워커는 `app.claim_job`으로 작업을 **5분 임대**합니다. 워커가 죽으면 임대가 끝난 뒤 다른 워커가 다시 가져갑니다(`attempts` 증가). 같은 작업이 두 번 동시에 실행되지는 않습니다.
- 외부로 보냈는데 결과를 모르면 `unknown_outcome`으로 둡니다. 자동으로 재시도하지 않습니다(이중 과금 방지). 관리자가 `/admin/jobs`에서 확인하고, 필요하면 `/admin/usage`의 정산(reconcile)으로 원장을 `settled`/`released`로 맞춥니다.
- 대기(`queued`/`waiting_external`) 작업은 학생 화면이나 `/admin/jobs`에서 취소할 수 있습니다. 이미 외부로 보낸 처리와 비용은 취소가 보장되지 않으며, 화면에도 그렇게 표시합니다.
- 긴급 중지: `/admin/providers`의 **외부 작업 모두 중지(kill)** 를 켜면 새 견적과 대기 중인 작업 실행이 모두 막힙니다. 기능별 스위치(AI·음성 문안·외부 조회)와 일일 한도(`/admin/usage`)는 리비전을 확인한 뒤 저장되므로, 동시에 수정하면 충돌로 거부됩니다.

## 4. 데이터 삭제·만료

- 학생 "내 데이터 삭제"(`/app/privacy`): 요청 즉시 접근을 막고 진행 중 제출을 철회합니다. 이어서 `user_deletion` 작업이 비공개 자료·파일·파생 결과를 지웁니다. 비용 원장과 보안 감사 기록은 회계·보안 보존 정책(기본 90일 제안)에 따라 남기고, 상태를 `partially_retained`로 표시하며 이유를 함께 적습니다. 학생 문안은 남기지 않습니다.
- 만료 정리(워커, 매시간 `purgeExpired`): 대상은 만료된 공급자 노트(레퍼런스가 참조하지 않는 것), 만료된 음성 문안, 만료된 idempotency 키(유료 작업 보유분 제외), 오래된 미사용 견적입니다. 정리 작업이 실패해도 조회 쿼리가 `expires_at`을 직접 검사하므로 만료 자료는 노출되지 않습니다.
- 삭제는 `app.allow_purge` 설정이 켜진 서비스 트랜잭션에서만 허용됩니다(실수로 인한 대량 삭제 방지).

## 5. 백업·복원 (파일럿 권고)

로컬 임시 DB는 백업 대상이 아닙니다. 파일럿 DB는 다음을 권고합니다(아직 자동화하지 않음).

1. 매일 `pg_dump --format=custom`으로 덤프하고, 비공개 파일 저장소도 같은 시점으로 스냅샷합니다. 백업은 암호화해 접근을 제한합니다.
2. 복원 후에는 백업 시점 이후 완료된 `deletion_requests`를 조회해 해당 사용자의 `user_deletion` 작업을 다시 실행합니다(삭제 tombstone 재적용). 이 절차는 **수동**입니다. "백업에서 즉시 소거된다"고 안내하지 않습니다.
3. 복원 리허설 결과(소요 시간, 재적용 건수)를 기록합니다.

## 6. 감사·모니터링

- 감사 기록: `/admin/audit`. 대상은 멤버 역할·중지, 초대, 기수, 스위치·한도, 공급자 허가, 자료실 공개·철회, 신고에 따른 비공개, 삭제 요청입니다.
- 오류·권리 신고: `/review/reports`. 오탐 신고는 규칙별로 집계해 점검 규칙 조정에 씁니다(규칙은 새 버전으로 바꾸며, 기존 결과는 바뀌지 않습니다). 자료실 권리·원본 삭제 신고는 즉시 비공개 처리됩니다.
- 로그에는 학생 원문을 남기지 않습니다. API 오류는 요청 ID와 마스킹된 메시지만 남기며, 키·토큰·전화번호 등은 `redactString`으로 가립니다.

## 7. live 전환 조건 (지금은 모두 미충족)

명세 6.3의 조건이 **모두** 참이어야 외부 호출이 실행됩니다. 현재 차단 상태와 근거는 README의 "live 차단 이유"에 있습니다. 전환 전에 필요한 것은 다음과 같습니다.

1. 공급자 다중 수강생 이용 허가 증빙을 `/admin/providers`에 기록(보관·표시·AI 가공 범위 포함).
2. 엔드포인트별 실제 단가·호출 한도 확인, 가격 버전 등록. 단가를 모르면 계속 차단됩니다.
3. live 예산 설정(기본 0), 최대 승인 금액.
4. RF08·RF10 파라미터와 미확인 문서(DCZW5V7A, 9UHXOXSF, tool/QPNFJRG1) 확인.
5. AI/OCR 제공자, 학생 데이터 전송 정책 결정.
6. 소량 실측(M5)으로 계약 fixture 확보. 그 전까지 live 어댑터는 "미검증"입니다.
7. 워커의 live 연결(게이트 컨텍스트를 DB 허가·가격·예산에서 구성)은 P0 범위 밖이라, live 모드로 시작하면 워커가 시작을 거부합니다.

## 8. 성능 기준 확인

`pnpm perf`를 실행하면 임시 DB에 합성 노트를 약 1만 건까지 복제한 뒤 주요 조회를 측정합니다. 측정 범위는 사용자 1명 반복과 동시 20명 혼합입니다. 명세 11장 파일럿 목표는 저장된 탐색 p95 2초, 일반 CRUD p95 1초입니다. 측정이 끝난 DB는 `pg_ctl -D .tmp/pg/data stop`으로 멈춥니다.
