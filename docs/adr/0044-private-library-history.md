# 0044 작성 이력 관리와 개인 목록 페이지

2026-10-20. 사용자가 작성 이력의 이전 버전 복원, 글 복제/검색/보관 및 내 사전/이력 페이지 구분과 학생 UI 점검을 요청했다.

- 이전 버전 복원은 현재 revision 확인 후 새 버전을 추가한다. 과거 snapshot은 변경하지 않고 restored_from에 원래 버전을 남긴다. 활성 임시 글이 있으면 먼저 정식 저장하도록 차단한다. 작성물 잠금과 임시 저장 잠금을 함께 사용한다.
- 복제는 마지막 저장본과 당시 단어/뜻을 새 UUID의 버전1로 복제한다. 숨겨진 사전 항목도 저장 당시 snapshot을 보존한다. 기존 글과 이력은 유지한다.
- 보관은 archived_at으로 표시하고 보관함에서 복귀할 수 있다. 보관 중에는 편집/임시쓰기/이전 버전 복원을 차단한다. 기존 이력과 임시 내용은 삭제하지 않는다.
- 새 UI 목록은 서버에서 소유자/조직/모드/검색/분류/보관조건을 먼저 적용하고 count+limit+offset으로 조회한다. 내 사전12개, 작성물10개, 이전 버전10개/페이지. 과거200개/100개/50개 UI 표시 제한을 해제한다. 정렬 동률은 UUID로 안정화한다.
- 페이지 번호가 범위를 벗어나면 유효한 마지막/첫 페이지로 보정한다. 검색어는 문자열 그대로 비교해 SQL 와일드카드 확대를 하지 않는다. 분류 선택지는 모든 활성 개인 항목에서 조회한다.
- 학생 UI는 현재 메뉴 표시, 모바일 메뉴 자동 가시화, 주요 조작44px, 본문 미리보기, 검색/보관함/초기화와 페이지 표시를 제공한다. 사전 선택은 현재 페이지에서만 유지하며 개수와 제한을 안내한다.
- 학생 UI의 변경 여정은 로컬 mock 계정에서 PC/모바일로 검증하고 성공 화면을 CI artifact로 보존한다. 운영에서는 배포/스키마/읽기 전용 화면 확인만 수행한다. 비용/스케줄 정책 및 외부 제공자 호출을 추가하지 않는다.
