# ADR 0008 — RF01 검색 연결과 "실패 요청 무과금" 반영

날짜: 2026-10-06 · 상태: 채택 (실측 전, 가짜 RedFox로만 검증)

## 근거

- 사용자가 전달한 RedFox 문서 「小红书爆款笔记洞察」(`POST /story/api/xhs/search/search`).
- RedFox 가격 계산기 안내: 호출당 과금, 일일 총 요청 수 기준 구간 할인, "실패한(200이 아닌) 요청은 과금하지 않음".

## 결정

1. **요청**: 문서에 있는 파라미터만 씁니다: `keyword`, `pageNum`/`pageSize`(키워드가 없을 때만 적용), `startDate`/`endDate`(yyyy-MM-dd). 기간은 중국 시간 기준 날짜로 보냅니다. 주제(topic) 필터는 공급자가 지원하지 않으므로 보내지 않고 `coverage.postFilters`에 표시합니다.
2. **응답 포장**: 문서는 "보통 code/message/data, 실제 서비스 기준"이라고 쓰면서 예시는 포장 없는 객체를 보여 줍니다. RF01에서만 두 형태를 모두 받되, 둘 다 스키마로 엄격히 검사합니다. 어긋나면 계약 위반입니다.
3. **매핑 원칙(추측 금지)**:
   - 노트 형식(영상/이미지) 필드가 없으므로 `note_type = null`로 둡니다. 그 결과로는 음성 문안 추출을 막고 "형식 미확인"으로 안내합니다.
   - 조회수가 없으므로 `views`는 미확인입니다. 저장률을 계산하지 않습니다.
   - `createTime`은 시간대 표기가 없어 중국 시간(UTC+8)으로 해석합니다. **첫 실측에서 확인할 항목**입니다.
   - 작성자 ID가 없으면 `author_ref = null`로 둡니다(참고 계정 후보에서 제외).
   - 표지 이미지(cover)는 저장하지 않습니다. 미디어 표시 권한이 정해지지 않았기 때문입니다.
   - 본문(desc)은 200자 발췌만 쓰고, 허가에 "발췌 표시"가 있을 때만 저장합니다.
   - 해시태그는 본문과 `topicsName`에서 추출합니다. 관련 검색어는 검토 전 키워드 후보(draft)로만 저장합니다.
   - `latestHotArticles`는 지금처럼 별도 표시하고 추천·집계에서 제외합니다. `hotTopics`와 점수 필드(popularity·recency·relevance·total)는 쓰지 않습니다. 점수는 공급자 내부 기준이어서 우리 추천 이유로 쓰지 않습니다.
   - 주제·형식 분류는 live 노트에 아직 적용하지 않습니다(빈 값). 그래서 탐색의 주제 필터에는 걸리지 않습니다.
4. **실패 요청 무과금**: HTTP 2xx가 아닌 응답은 `ProviderHttpError`로 처리합니다. 공급자 안내대로 과금이 없고 공급자 쪽에 효과도 없다고 보고 예약을 반환합니다. 음성 문안 제출도 "결과 확인 필요"가 아니라 실패(`provider_failed`)로 끝납니다. **HTTP 200인데 code가 2000이 아닌 경우**는 과금 여부를 모르므로 지금처럼 보수적으로 처리합니다: 예약 유지, 관리자 정산.
5. **구간 할인**: 단가는 가장 비싼 구간(소량 사용) 값을 등록합니다. 예약이 실제 청구보다 크게 잡히는 쪽으로 안전합니다.

## 검증

- 단위 계약 테스트 4개(합성 데이터, 문서 형태):
  - 문서 파라미터만 전송, 키는 헤더로만
  - 포장 있는/없는 응답 모두 처리
  - 누락 필드는 null 유지, 잘못된 ID는 버림
  - 실패 분류: 스키마 위반, 업무 코드, 무과금 HTTP 오류, 게이트 차단
- DB 테스트 1개: 견적 0.06 → 동의 → 적재(발췌 없음, 형식 null) → 정산, 502 응답 시 예약 반환.

## 추가: 실제 응답 1건으로 확인한 사항 (2026-10-06)

사용자가 직접 실행한 RF01 실제 응답 1건(키워드 `AIGC创业`, 2026년 7월)을 받아 대조했다. 이 앱은 호출하지 않았다.

- **응답 포장**: 다른 엔드포인트와 같은 `{code: 2000, msg, data}` 형태였다. 그래서 포장 없는 본문 허용을 없앴다. 이제 포장이 없으면 계약 위반이다.
- **시간대**: `createTime`은 UTC+8이다. 노트 ID 앞 8자리(16진수 유닉스 시각)와 6건 중 5건이 정확히 8시간 차이였다. 나머지 1건은 +9시간 6분 차이였는데, 노트를 만든 뒤 늦게 발행한 경우로 보인다. 즉 `createTime`은 발행 시각이다.
- **`pageSize`**: 키워드가 있을 때 10을 보내도 50으로 응답했다. 문서대로 무시된다.
- **`total`과 반환 수**: `total` 4, 반환은 1건이었다. 안내 문구(`tips`)는 "4건만 찾음"이었다. 공급자 총수와 안내 문구를 `coverage.providerTotal`/`providerTip`으로 저장해, 반환 수와 구분해 보여 줄 수 있게 했다.
- **`latestHotArticles`·`hotTopics`**: 검색어와 무관한 전체 인기 글·주제였다(생활·사진·손공예 등). 지금처럼 결과로 쓰지 않고 별도 표시하며, 추천·집계에서 제외한다.
- **노트 형식·조회수**: 실제 응답에도 없었다. 형식 미확인, 조회수 미확인을 유지한다.
- **계약 예시**: 원본에는 실제 작성자 닉네임·ID가 있어 저장하지 않았다. 구조·타입·null 여부·노트 ID 시각 부분만 보존한 익명 사본을 `tests/fixtures/redfox/rf01-live-2026-10-06.sanitized.json`으로 두고 계약 테스트(시간대 검증 포함)에 쓴다.
- **아직 미확인**: RF01 단가와 통화, HTTP 200인데 오류 코드인 응답의 과금 여부, 페이지 넘김(키워드 검색은 페이지 파라미터가 무시되므로 한 번에 최대 몇 건인지).
