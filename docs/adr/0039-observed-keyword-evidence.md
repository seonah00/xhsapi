# 0039. 실사용 태그와 검색 후보를 구분하고 게시물 반응을 비교한다

상태: 구현, 검증 중 (2026-10-15)

## 배경

운영자는 AI가 만든 표현이 실제 샤오홍슈 태그인지, 반응이 좋은 게시물에서 쓰이는지 확인하고 싶다. 현재 공급자 연결은 조회수를 제공하지 않으므로 좋아요·저장 수를 조회수나 검색량으로 표현하지 않는다.

## 결정

- 현재 권한이 있는 검색 표본 최대 50건에서 정확한 태그(공급자 태그 또는 제목·본문의 해시태그)가 확인된 항목만 실사용 목록에 표시한다. 일반 본문 단어의 출현을 해시태그 사용으로 세지 않는다.
- 동일 플랫폼 게시물은 최신 관찰 1개만 사용한다. 알려진 작성자 수, 관찰·게시 날짜 범위, 정확한 좋아요·저장·댓글·조회수의 중앙값과 지표별 유효 표본 수를 계산한다. 미제공·반올림·범위 수치는 정확한 중앙값에서 제외하고, 0은 유효한 값으로 유지한다.
- 비교 표본 충분은 게시물 3건 이상·확인된 작성자 2명 이상·정확한 저장 수 3건 이상이다. 이는 내부 표본 기준이며 플랫폼 인기 인증이 아니다. 기본 정렬은 이 기준 충족 여부 후 저장 중앙값이다. 좋아요·사용 게시물 수 정렬도 제공한다.
- 실사용 롱테일은 실제 태그 중 검색 주제를 포함하고 더 구체적인 구문을 별도 분류한다. 분류는 검색 방향이며 성과 보장이 아니다.
- 사전·편집 시드·AI가 제안한 미관찰 후보는 접힌 검증 전 목록으로 분리한다. 선택·복사를 비활성화한다. 후보 생성은 실사용 근거를 만들지 않는다.
- 후보의 실제 게시물로 검증 버튼은 기존 searchAutomatically → requestAutoSearch 경로를 사용한다. 공급자·예산·월 한도·동의·캐시·중복 방지를 유지하고 검색 화면으로 이동한다. 검색 완료 시 갱신된 표본에서 다시 정확한 태그 사용과 반응을 집계한다. 후보 전체를 몰래 일괄 검색하지 않는다.
- 이미 발견한 태그도 근거 게시물 최대 3개와 추가 검색 버튼을 제공한다. 키워드 검색량이나 태그로 인한 효과를 추정하지 않는다.

## 한계

수집 표본은 검색 정렬과 수집 범위에 편향된다. 본문 발췌·태그 누락 때문에 미관찰이 미사용을 뜻하지 않는다. 게시물 반응과 태그 성과 사이 인과관계는 확인하지 않는다. 기존 AI 확장의 실제 성공 미검증 상태는 이 변경으로 해결됐다고 간주하지 않는다. 실 AI 재검증에는 별도 비용 범위가 필요하다.

스키마·수집 계약·사용자 권한 변경 없음. 이번 개발 테스트는 모의 응답만 사용한다.
