# 0048. 탐색에는 원문 열림을 확인한 live 게시물만 표시

2026-10-21 · Accepted

## 문제와 결정

공유주소 보관과 원문 페이지 열림은 다르다. 보관된 주소의 브라우저 점검에서 404로 확인한 항목이 학생 탐색에 계속 표시됐다. 게시물·공유주소는 삭제하지 않고 `note_link_checks`에 주소를 포함하지 않는 점검 상태(`opened` / `not_found`), 점검 시각과 방법만 별도 보관한다. 상태 행이 없으면 미확인이다.

live 탐색은 열림 확인 상태와 현재 유효한 공유주소를 모두 요구한다. 검색·카테고리·정렬·새 작업 결과·최신 인기·추천에 같은 조건을 적용하며, 필터링은 LIMIT/OFFSET 이전이다. 탐색 화면은 관리자에게도 같은 목록을 보여준다. 기존 상세·개인 저장·이력의 접근 권한과 데이터는 유지한다. mock 자료는 실제 원문이 없으므로 이 조건에서 제외한다.

## 권한과 적용

점검 상태는 서비스만 쓴다. 회원은 기존 notes RLS로 읽을 수 있는 소속 게시물의 점검 상태만 읽는다. URL·토큰·실제 게시물 ID를 마이그레이션이나 테스트 fixture에 넣지 않는다. 기존 브라우저 점검 결과를 해당 조직·live 모드·게시물 ID 및 플랫폼 ID로 일치시킨 뒤 운영 데이터로 별도 반영한다. 확인된 404와 미확인은 탐색에서 숨기지만 복구 후보로 보관한다.

유료 API 호출, 자동 재시도, 예산 증액, 정기 수집이나 자동 브라우저 검증은 추가하지 않는다. 이후 새 수집 결과는 보관되더라도 열림을 확인하기 전에는 학생 탐색에 나오지 않는다. `opened`는 점검 당시의 페이지 열림이며 미래의 로그인·플랫폼 제한이나 영상 전체 재생을 보장하지 않는다.

## 검증

합성 DB 회귀: 정상 52건의 50+2 페이지 분할, 404 19건·미확인·링크 만료·최신 인기 제외, 검색/정렬/원문 필터, 원본 및 상세 유지, mock 호환, 비회원 조회 및 학생 쓰기 거부. 전체 타입·린트·단위·DB·학생 E2E와 운영 읽기 검증을 수행한다.
