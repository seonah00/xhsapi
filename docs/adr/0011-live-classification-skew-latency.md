# ADR 0011: live 노트 분류, 배포 직후 버튼 오류, DB 왕복 줄이기

날짜: 2026-10-07 · 상태: 채택

1. **live 노트 분류**: RF01/RF02 결과에는 우리 주제·형식 분류가 없다. 그래서 `@xhs/domain`의 키워드 분류기(`classifyNote`, `keyword-v1`)로 붙인다.
   - 입력: 제목, 저장한 발췌, 태그만 쓴다.
   - 신뢰도: 항상 `low`로 저장해 공급자 매핑(`provider-map-v1`, `medium`)과 구분한다.
   - 맞는 키워드가 없으면 분류하지 않는다.
   - 키워드 목록은 이 프로젝트에서 직접 작성했다.
   - 이미 저장된 live 노트는 다음 조회에서 다시 받을 때 분류된다(일괄 소급 없음).
2. **배포 직후 버튼 오류**: 재배포 전에 열린 페이지가 없어진 서버 액션을 호출하면, 라우트 오류 경계(`components/route-error.tsx`)가 이를 감지한다(`unstable_isUnrecognizedActionError`).
   - 감지하면 한 번 자동으로 새로고침한다.
   - 1분 안에 다시 실패하면 "요청은 처리되지 않았습니다(비용 없음)"라고 안내하고 멈춘다.
   - 해당 요청은 서버에 닿지 않았으므로 작업·비용이 생기지 않는다.
3. **DB 왕복 줄이기**: `withUser`의 `begin` / `set_config` / `set local role`을 한 번의 쿼리로 보낸다.
   - Railway와 Supabase가 멀리 있을 때 요청마다 왕복 2번을 줄인다.
   - 사용자 ID는 UUID 형식 검사를 통과한 값만 SQL에 넣는다.
   - 지역을 맞추는 것(운영 설정)이 여전히 가장 큰 개선이다.

검증: 단위 104, DB 128, E2E 기본 13(새 `skew.spec.ts` 포함), Supabase 모드 1. 모두 통과했고 외부 연결 시도는 0건이다.
