# ADR 0005 — M4 전체 P0 검수 결정

날짜: 2026-10-05 · 상태: 채택

## 맥락

`XHS_STUDIO_ACCEPTANCE_TESTS.md`가 저장소에 없어 명세서 F01~F15, 10~12장을 기준으로 P0 누락을 대조했다. 누락으로 확인된 것은 F14 참고 계정 화면, 탐색의 "외부 자료 새로 조회"(mock), F03 조직 분류 관리, 11장 오류·권리 신고였다.

## 결정

1. **F14 참고 계정은 저장 자료 기반.** 후보는 조직에 저장된 노트의 작성자(`author_ref`)를 묶어 만든다. 공급자 성장 순위·팔로워 추이는 연결 전이므로 "제공하지 않음"으로 표시하고 만들어 채우지 않는다. 참고 계정은 `reference_accounts`에 저장 시점 스냅샷(`basis: stored_notes`)으로 저장하며 학생 본인 계정·성과와 섞지 않는다. 비교는 최대 3개.
2. **외부 자료 새로 조회는 견적→확인→작업.** 다른 비용 작업과 같이 `provider_search` 견적(5분·1회용)을 받고 확인해야 `app_jobs`에 들어간다. mock 모드에서는 합성 픽스처만 적재한다.
3. **신고는 대상 ID·사유·짧은 메모(200자)만.** 학생 문안은 첨부하지 않는다. 점검 결과 오탐 신고의 규칙 키는 **신고 시점에 신고자 권한으로 스냅샷**한다. 강사는 학생의 비공개 점검 결과를 읽을 수 없기 때문이다(RLS 유지). 자료실 항목의 `rights_issue`/`source_removed` 신고는 즉시 비공개(`revoked`) 처리하고 감사 기록을 남긴다.
4. **분류는 삭제하지 않고 비활성화.** 기본 주제·형식(전역)은 고정이고, 조직 전용 세부 주제·목적·지역·검색 시드만 추가한다. DB에 삭제 금지 정책(restrictive)을 둔다.
5. **mock 모드 외부 연결 차단을 런타임에서 강제.** 웹 서버(`instrumentation.ts`)와 워커가 `net.Socket#connect`를 감싸 루프백·DB 호스트 외 연결을 DNS 조회 전에 거부하고 로그를 남긴다. E2E는 이 로그가 하나라도 있으면 실패하고, 브라우저 요청이 앱 출처를 벗어나지 않는지도 검사한다.
6. **E2E는 프로덕션 빌드로 실행.** `next dev`는 자체 버전 확인으로 npm 레지스트리에 접속하려 해 위 가드에 걸렸다(앱 코드가 아님). 기본 E2E를 `next build && next start`로 바꿔 배포와 같은 CSP(unsafe-eval 없음)에서 검증한다. `E2E_DEV=1`로 dev 서버를 쓸 수 있다.
7. **접근성은 axe-core(WCAG 2.1 A/AA) 자동 검사 + 기존 키보드·라벨 규칙.** 강조색을 `#c42a45`로 바꿔 흰 배경·연한 강조 배경 모두 4.5:1 이상을 맞췄고, 어두운 테마는 강조 배경 위 글자색 토큰(`--color-on-accent`)을 둔다.
8. **조직 탈퇴(멤버 스스로 떠나기)는 P0에서 제외.** 관리자가 멤버를 중지할 수 있고, 학생은 "내 데이터 삭제"로 데이터를 지울 수 있다. 자발적 탈퇴는 마지막 관리자 보호·제출물 처리 규칙과 함께 다음 단계에서 설계한다.

## 결과

- 마이그레이션 `20261005000011_reports_taxonomy.sql`: `result_reports`(RLS), `app.report_library_item`, 분류 삭제 금지, 작성자·참고 계정 인덱스.
- 성능 측정 스크립트 `scripts/perf.ts`(노트 1만 건·동시 20명). 참고 계정 후보 쿼리를 상관 서브쿼리에서 집계 조인으로 바꿔 약 600ms → 270ms.
- 남은 위험: Next.js 인라인 스크립트 때문에 CSP `script-src`에 `'unsafe-inline'`이 남아 있다. 사용자 HTML을 렌더링하지 않고(`dangerouslySetInnerHTML` 없음) React가 이스케이프하므로 즉시 위험은 낮다. 배포 전 nonce 기반 CSP로 바꾸는 것을 권한다.
