# ADR 0006 — 출시 준비(승인 없이 가능한 범위)

날짜: 2026-10-05 · 상태: 채택

## 맥락

P0(M0~M4)를 끝낸 뒤 다음 단계는 M5(실데이터 소량 검증)입니다. M5에는 공급자 이용 허가, 실제 단가, 예산, 테스트 범위, 서버 secret이 필요하고 별도 승인 대상입니다(명세 13장). 그 전까지는 외부 호출 없이 할 수 있는 출시 준비만 진행했습니다.

## 결정

1. **ESLint 도입.** `typescript-eslint` 권장 규칙과 `react-hooks` 규칙을 씁니다. 추가 금지 규칙은 두 가지입니다: `dangerouslySetInnerHTML` 금지(XSS), 클라이언트 컴포넌트의 `process.env` 접근 금지. `pnpm lint`는 경고 0을 요구하며 `test:all`에 포함됩니다.
2. **nonce 기반 CSP.** `src/proxy.ts`가 요청마다 nonce를 만들고 `script-src 'self' 'nonce-…' 'strict-dynamic'`을 적용합니다. 스크립트에 대한 `'unsafe-inline'` 허용은 없습니다. `'unsafe-eval'`은 개발 서버에서만 씁니다. 루트 레이아웃이 요청 헤더를 읽어 모든 페이지를 동적 렌더링으로 두므로 nonce가 항상 적용됩니다. `style-src`는 style 속성 때문에 `'unsafe-inline'`을 유지합니다(사용자 HTML은 렌더링하지 않음). API 응답은 `default-src 'none'; sandbox`입니다.
3. **자발적 조직 탈퇴(ADR 0005의 8번을 대체).** 처리 순서는 다음과 같습니다.
   - 확인 문구를 입력해야 합니다.
   - "내 데이터 삭제"와 같은 즉시 차단 단계를 거칩니다: 공유 철회, 제출 철회.
   - 멤버십을 `left`로 바꾸고, 기수 배정을 해제하고, 감사 기록을 남깁니다.
   - 이후 `user_deletion` 작업이 그 조직의 데이터를 삭제합니다. 다른 조직의 데이터는 그대로입니다.

   마지막 활성 관리자는 기존 트리거로 막힙니다. 탈퇴한 멤버는 관리자가 재활성화할 수 없고, 새 초대 링크로만 다시 활성화됩니다. 멤버십 행은 감사·외래키 무결성 때문에 삭제하지 않습니다.
4. **삭제 작업과 멤버십 검사 분리(결함 수정).** 워커는 소유자가 활성 멤버가 아니면 작업을 `membership_revoked`로 실패시킵니다. 그래서 삭제를 요청한 뒤 중지되거나 탈퇴한 사용자의 삭제가 실패할 수 있었습니다. `user_deletion`은 이 검사에서 제외합니다.
5. **워커 live 연결 대신 live 전환 점검표.** live 모드에서는 단가 미확인으로 견적 단계부터 차단되므로, 지금 워커의 live 경로를 만들어도 실행 경로가 없습니다. 그 작업은 실제 가격 체계와 함께 M5에서 설계합니다. 대신 `/admin/providers`에 엔드포인트별 점검표를 둡니다. 이 점검표는 실제 `evaluateLiveGate`를 조직의 저장 상태로 평가해 차단 이유를 보여 주며, 외부 호출은 하지 않습니다. 동의·요청별 견적·예산 예약은 요청할 때 확인하는 항목이라 별도로 표시합니다.

## 결과

- 마이그레이션 `20261005000012_org_leave.sql`.
- 테스트: 탈퇴(DB 3개, E2E), live 점검표(DB 3개: 출고 상태 전부 차단, 모든 조건 충족 시에만 준비됨, 관리자 전용), CSP(E2E: 모든 script 태그 nonce, 요청마다 다른 nonce, 위반 0).
